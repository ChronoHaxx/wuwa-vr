WUWA VR — WINDOW-STARTUP COMPATIBILITY BETA CHECKS
Desktop app 1.0.6 | beta-2026-10-06-window-startup
VR build window-startup-20261006 | game 3.7

The affected Windows 11 Steam PC still failed to reach VR in 1.0.5. This follow-up repairs an unchecked DirectX 12 window lookup: it queries the supported interface and falls back to the base swapchain description when needed, while retaining window validation. Steam process checks now use limited access and retain verified identity only while the same process handle is alive. Repeated log lines are compacted so startup transitions remain visible. These are compatibility repairs and better evidence, not a confirmed fix on that PC; its retest and headset acceptance remain pending.

Record Pass / Fail / Blocked / Not tested, with Windows version, game store,
app/package/build versions and the exact visible result. No need to manufacture
failures or repeat every earlier feature check just to try this update.

[ ] 1. Update BOTH parts. Step 02 > Versions & updates > Check updates >
    Update launcher, then Restart to update when the game, injector, recording
    and other operations are idle. Confirm app 1.0.6. Explicitly select and
    install beta-2026-10-06-window-startup in Step 02; confirm VR build
    window-startup-20261006. An app update preserves the old package selection;
    Check updates does not select the new VR package automatically.
    If the old app blocks updating, close it and use the new WuWa-VR-Setup.exe
    from https://chronohaxx.github.io/wuwa-vr/. Reinstallation preserves data
    and does not guarantee that a stuck worker has stopped.
[ ] 2. One controlled launch. Keep your intended Steam/Kuro install and runtime.
    Click Launch in VR once and accept Windows permission if requested. For
    Kuro, press Play in its launcher. Check the actual game/VR view, not just
    a loaded-DLL message or a spinner. Confirm UEVR settings open with L3+R3.
    If it still fails, use Troubleshooting > Copy diagnostics before retrying;
    include the attempt's backend.log if available. No second injector in parallel.
[ ] 3. Clear failure/recovery. If startup fails or waits indefinitely, its stage
    and reason should stay visible. Stop waiting requests cancellation; it does
    not stop the game. If the worker does not acknowledge cancellation, use
    Troubleshooting > Stuck launcher processes > Find stuck launcher processes.
    Scan stops nothing; review PID, role, time, path and eligibility. Select only
    the verified helper/startup worker you intend to stop, then confirm Stop
    selected. Game/Steam/runtime/injector processes are not termination targets;
    runtime/profile work and active/unknown recording remain protected.
    Review individual results before Retry connection. Close launcher only exits
    the window without claiming the background worker stopped.
[ ] 4. Normal use. Check L3+A recenter, L3+B HUD toggle and your existing view
    mode. Exit normally; another intentional launch should remain available.
    Test headset output separately and stop if uncomfortable. Optional walking,
    rim-light suppression and automatic cinema keep their existing limits.
[ ] 5. Rollback, only if needed. Close the game and injector and stop recording.
    Troubleshooting > Repair & recovery > Use previous installed version selects the previous retained
    VR package; it does not downgrade the desktop app. Keep the old package and
    backups. Its known renderer-startup problem may return on the affected PC.

Existing safeguards remain: runtime selection is explicit, Copy diagnostics is
local, and no diagnostic upload is automatic. Prepare uninstall confirms cleanup
of verified idle downloads; Windows uninstall also attempts bounded cleanup.
Active OpenXR packages, busy/unverified files, settings, backups and recordings
are retained with reasons. Do not delete data folders to work around an update.

PlayerGuide.html / README.txt describe all controls and known limits. Far NPC
rim lighting, scene/dialogue stalls, HUD refresh and flat-menu backgrounds are
not claimed fixed by this renderer-startup change.

鸣潮 VR — 渲染器启动测试版检查
桌面应用 1.0.6 | beta-2026-10-06-window-startup
VR 构建 window-startup-20261006 | 游戏 3.7

受影响的远程 Windows 11 Steam 电脑在 1.0.4 中已载入 VR DLL，但没有接收到
实际游戏渲染帧。新后端在尚未识别实际渲染器时尝试另一种图形挂钩，并为每次
启动保存 backend.log；不改变已识别到的渲染器，也不能证明问题由显卡品牌造成。
原生后端已编译，隔离图形挂接测试已通过；远程电脑启动及头显验收仍待完成。
载入 DLL 本身不等于 VR 启动成功。

记录通过／失败／受阻／未测试，并注明 Windows、游戏平台、应用／包／构建版本
及实际结果。无需刻意制造故障，也无需为本次更新重复所有旧功能检查。

[ ] 1. 两项都更新。第 02 步 > 版本与更新 > 检查更新 > 更新启动器，待游戏、
    注入器、录制及其他操作结束后重启并更新，确认应用为 1.0.6。再明确选择
    并安装 beta-2026-10-06-window-startup，确认构建 window-startup-20261006。
    更新应用会保留旧 VR 包选择；检查更新不会自动改选新包。旧应用阻止更新时，
    关闭后运行网站的新 WuWa-VR-Setup.exe。重装保留数据，也不保证卡住的任务已停止。
[ ] 2. 启动一次。保留所需的 Steam／库洛安装及运行时，点击一次“以 VR 模式启动”，
    按需同意 Windows 授权；库洛版在其启动器点击开始。检查实际游戏／VR 画面，
    不只看 DLL 载入提示或转圈。确认 L3+R3 可打开 UEVR 设置。仍失败时先在
    故障排查中复制诊断，并附上该次启动的 backend.log（若有），再考虑重试。
    不要同时运行第二个注入器。
[ ] 3. 失败与恢复。应明确显示启动阶段及原因。“停止等待”仅请求取消等待，不结束
    游戏。未收到取消确认时，在故障排查 > 卡住的启动器进程中执行查找。扫描不停止
    进程；核对 PID、角色、时间、路径及可停止状态，只选择确实想停止且已验证归属的
    辅助程序／启动任务，再确认停止所选进程。游戏、Steam、运行时及注入器不属于
    终止目标；运行时／配置任务及正在录制或状态不明的录制受保护。
    查看逐项结果后再重试连接。“仅关闭启动器窗口”不表示后台任务已停止。
[ ] 4. 正常使用。检查 L3+A 重新居中、L3+B 界面开关及原有视图模式。正常退出后
    应能再次明确启动。头显输出另行验收，不适时停止。可选漫游、边缘光抑制及
    自动影院的原有限制不变。
[ ] 5. 仅在需要时回退。关闭游戏及注入器、停止录制后，在故障排查 > 修复与恢复
    点击“使用上一个已安装版本”，选回上一个保留的 VR 包；不会降级桌面应用。保留旧包及备份。
    受影响电脑回退后可能重新出现旧版的渲染器启动问题。

运行时仍需明确选择，诊断只保存在本机，不自动上传。“准备卸载”确认后清理空闲且
已验证的下载文件，Windows 卸载也会尝试限时清理。使用中的 OpenXR 包、忙碌或
无法验证的文件、设置、备份及录像会保留并说明原因。不要删除数据目录来更新。
完整控制和限制见 PlayerGuide.html／README.txt。本次不宣称修复远处 NPC 轮廓光、
场景／对话停顿、HUD 刷新或平面菜单背景问题。
