Play WuWa in VR

Public beta 1.0.0 · game 3.7. Advanced tools are one footer link away.

Run WuWa-VR-Setup.exe once to install for your Windows user, then open the normal WuWa VR shortcut. No separate Python installation is needed. This small installer does not bundle the VR mod: the first Install VR needs internet to download about 54 MB.

01 · Find your game

Your saved or default official game launcher should appear automatically. Use Change only if it is missing or wrong.

02 · Install or update WuWa VR

This card shows the VR version and the game version it targets. Review the compatibility and account-risk notice, then use the main Install VR button. Expand Versions & updates to choose another package or check updates. The download is verified before installation; installation does not start the game.

If an update check fails, read the displayed error and retry with an internet connection. A cached version list does not establish that it is the latest public version.

03 · Connect and launch

Start your headset connection software. Check the displayed runtime: Use headset is for headset play; Use bundled simulator is for a desktop preview. Switching requires the game and injector to be closed and may request Windows permission.

Select Launch in VR, accept Windows permission if requested, then press Play in the official game launcher. On later visits, your saved choices let you go straight to Launch in VR.

This is an unofficial community mod. Injection may trigger anti-cheat or account restrictions. It is not approved by Kuro Games. The launcher does not accept this notice for you.

Updates and portable fallback

Open 02 → Versions & updates → Check updates. Desktop app: choose Update launcher to download and verify the update; this does not restart the app. When it is ready, close the game and injector, stop recording and finish other operations, then choose Restart to update and confirm. Installing or updating the desktop app preserves your selected VR package. VR package: in step 02 choose beta-2026-10-04-launcher and install it, or select it if already installed, to use npc-rim-20261004 (formerly the private NPC-rim candidate). Settings, backups, logs and recordings stay in their existing folders.

Advanced fallback: download WuWa-VR-Launcher.zip from the same release, extract everything and open WuWa VR Launcher.exe. Keep its app and python folders together. This older web interface does not self-update the desktop app. The previous public beta remains available.

Recording and advanced tools

The footer's Developer tools link opens the original web interface for the selected package. It retains recording, playtests, advanced settings and logs. Recording supports SteamVR and the bundled simulator; audio and VDXR capture are not supported.

If something is wrong

Open Troubleshooting in the footer. Controller check reads all four XInput slots, HidHide visibility settings and known input helpers. Refresh reruns the check; Copy report copies a sanitized summary. It works without the web helper and changes no driver or controller settings. Connected means visible to this launcher, not proof of working buttons in the game.

For controller-only play, close an unneeded remapper normally, then refresh the check. Keep intentional treadmill/remapping setups intact. Repair and rollback are also here; close the game and injector before changing packages. Back returns to the home screen.

NPC rim lighting workaround · 4 Oct public beta

Release beta-2026-10-04-launcher / backend npc-rim-20261004. The owner confirmed the retained headset 2D-brightness and ultimate-camera corrections in earlier builds. The new rim toggle still needs physical-headset checking. Fresh-PC installation and Steam/Epic game injection remain unverified; see the release receipt for build/package results.

Optional NPC rim workaround — default off

Press L3 + R3 to open UEVR, then choose VR → WuWa Controls → Suppress mismatched NPC rim lighting. Your chosen setting can be saved. It removes the toon-depth rim effect from all characters using it, including intended nearby rim lighting. It is not limited to distant NPCs.

Two repeated simulator comparisons in one stationary NPC scene reduced the extra right-eye contour at zero rim width; restoring the prior value brought it back. This supports a visual workaround, not an underlying stereo shader repair. Headset acceptance and other scenes remain pending.

Turning it off restores the captured prior value while still owned. Entering 2D or leaving active native VR also restores it; returning to eligible normal VR reapplies suppression if enabled. External changes are preserved. Read the status below the option; a restoration failure is not success. If prompted, turn it off, then on to retry restoration before reapplying.

When you choose to test: compare a fixed distant NPC, check the nearby visual tradeoff, then check 2D/return and Off restoration. See TEST THIS.txt. Existing features need only relevant regression checks.

Retained view controls

The player confirmed headset 2D brightness in the previous view-controls build; this candidate retains that correction. Separate HUD/menu transparency, RGB/gamma, eye ordering and earlier accepted rendering fixes remain unchanged.

To toggle stereoscopic 2D, fully hold LT and RT first, then hold L3 for 0.8 seconds. Release all three before repeating; close UEVR and HUD/mouse adjustment. Dialogue is supported. If the HUD is squashed after returning, use VR → WuWa Controls → Reset HUD aspect and read its result. It does not send ESC or change saved HUD size/position.

Horizontal Projection and Vertical Projection defaults remain Raw / default; saved choices are unchanged. The separate timed projection comparison is inactive and cannot start while rim suppression would confound it.

Cutscenes can still lose the right-eye scene or flicker. The player finds manual stereoscopic 2D useful; automatic cutscene switching is not provided.

Existing optional Quest walking controls

Open VR → WuWa Controls → VR controllers for walking (optional) → Walking input. It starts Off each launch. Use OpenXR, wake both controllers, focus the game, then release VR buttons, grips and triggers and center both sticks to arm. Repeat after focus loss, reconnect, mode changes or opening/closing UEVR. First person remains a separate existing choice; camera and aim settings are unchanged.

VR controllers only supplies slot 0: left stick moves, right stick looks. VR + treadmill / Xbox slot 0–3 merges with your explicitly chosen connected slot. Inspect Troubleshooting → Controller check, then confirm your device's slot; the number alone cannot identify RealityRunner. Merge preserves the device's left-stick movement, even when neutral. VR adds buttons and right-stick look; moving the physical right stick beyond its deadzone gives that device both look axes.

Quest A/B/X/Y match their printed labels; triggers = LT/RT, grips = LB/RB, stick clicks = L3/R3. Left Menu = Start; left grip + Menu = View (consumes LB). Both stick clicks open/close UEVR. UEVR menus use the VR left stick even in merge mode; treadmill movement does not scroll the menu. No Quest system-button or D-pad mapping is added; this is a sightseeing layout, not a complete combat layout.

Physical gamepad passthrough or a conflicting slot filter blocks VR input. No driver, HidHide, RealityRunner or system settings are changed. Off (normal input) restores your existing ControllersAllowed behavior: if already ON, legacy VR controller mapping resumes. Off does not disable that pre-existing mapping.

If you choose to test, check only the relevant walking regressions in TEST THIS.txt: RealityRunner merge and menu navigation, held-input recovery, shortcuts and Off/restart. Mark Pass / Fail / Blocked / Not tested explicitly. Previous features need only relevant regression checks. Stop if movement is uncomfortable; this mode does not fix rendering issues.

Xbox remains the default gameplay input. Optional diorama, optical hand visualization and menu comfort start off. Hands are a visualization demo, not grabbing or gesture gameplay.

Existing Xbox view toggles

Close UEVR settings and game menus, and leave HUD/mouse adjustment. Hold L3 (click the left stick), then fully squeeze LT for the portal or RT for diorama. Keep the other trigger released; release all controls before repeating. F7 still toggles the portal. Physical gamepad passthrough bypasses these controller shortcuts.

Diorama temporarily uses 10× world scale with Native Stereo, with the portal on or off; AFR disables it. Toggle it off to return to your normal saved scale, including deliberate scale edits. It starts off each launch, settings reload and runtime reinitialization. Head movement is magnified; L3 + A recenters. The menu toggle remains under VR → WuWa Controls → Diorama mode (optional).

These shortcuts are retained from the 4 October controller-toggles revision. Check their regression with the new walking inputs; prior component results do not establish this candidate's physical acceptance. No new keyboard shortcut is added.

Existing headset-confirmed ultimate-camera behavior is retained. New optional features still need physical checks. The underlying NPC stereo-lighting cause and Weapon/Echo submenu reflections remain unresolved. Consult TEST THIS.txt for the grouped checklist and current evidence limits.

开始体验鸣潮 VR

公开测试版 1.0.0 · 游戏 3.7。底部链接保留完整开发工具。

运行 WuWa-VR-Setup.exe，为当前 Windows 用户安装，再打开普通 WuWa VR 快捷方式。无需另行安装 Python。小型安装程序不包含 VR 模组；首次安装 VR需要联网下载约 54 MB。

01 · 查找游戏

应用会自动查找已保存或默认位置的官方启动器。仅在缺失或错误时点击更改。

02 · 安装或更新 VR

此处显示 VR 版本及其对应的游戏版本。阅读兼容性和账号风险提示后，点击底部主按钮安装 VR。需要时展开版本与更新以选择安装包或检查更新。下载包会先验证；安装不会启动游戏。

更新检查失败时请读取错误并联网重试；缓存版本列表不代表它是最新公开版本。

03 · 连接并启动

先启动头显连接软件，再确认显示的运行时。使用头显用于头显游戏，使用内置模拟器用于桌面预览。切换前需关闭游戏及注入器，并可能需要 Windows 授权。

点击以 VR 模式启动，在需要时同意 Windows 授权，然后在游戏官方启动器内点击开始。以后使用已保存的选项即可直接进入启动流程。

这是非官方社区模组，未经库洛游戏认可。注入可能触发反作弊或账号限制。启动器不会代替你接受风险提示。

更新与便携备用方式

打开第 02 步 → 版本与更新 → 检查更新。桌面应用：选择更新启动器以下载并校验更新；此时不会重启应用。更新就绪后，关闭游戏和注入器，停止录制并完成其他操作，再选择重启并更新并确认。安装或更新桌面应用会保留当前选择的 VR 包。VR 包：在第 02 步选择 beta-2026-10-04-launcher 并安装（已安装时直接选用），即可使用 npc-rim-20261004（原私测 NPC 轮廓光候选版）。设置、备份、日志和录像保留在原有文件夹中。

进阶备用方式：从同一发布页下载 WuWa-VR-Launcher.zip，完整解压后打开 WuWa VR Launcher.exe，保持 app 和 python 文件夹完整。这是旧版网页界面，不会自动更新桌面应用。上一个公开测试版仍可获取。

录制与开发工具

底部开发工具打开当前安装包的原版网页界面，保留录像、测试、高级设置和日志。录像支持 SteamVR 及内置模拟器；暂不支持音频和 VDXR。

遇到问题

打开底部故障排查。手柄检查只读取四个 XInput 插槽、HidHide 可见性设置及常见输入辅助程序，可刷新和复制脱敏报告。不依赖网页辅助程序，也不更改驱动或手柄设置。检测到手柄只代表启动器可见，不能证明游戏已收到按键。

仅用普通手柄时，可正常退出不需要的映射程序后重新检查。使用跑步机或主动配置映射时请保留原设置。修复及回退也在这里；更换安装包前需关闭游戏和注入器。点击返回回到首页。

NPC 边缘光临时方案 · 10 月 4 日公开测试版

发布版本 beta-2026-10-04-launcher／后端 npc-rim-20261004。作者此前已确认头显二维亮度与大招镜头修正，本版保留这些改进。新增边缘光开关仍待头显验证；全新电脑安装与 Steam／Epic 游戏版本注入也未确认。构建及安装包测试结果请参阅发布记录。

可选 NPC 边缘光方案——默认关闭

按 L3 + R3 打开 UEVR，在 VR → WuWa Controls → 抑制不匹配的 NPC 边缘光（Suppress mismatched NPC rim lighting）开启。所选状态可以保存。它会移除所有使用该效果的角色的卡通深度边缘光，包括近处角色原本应有的边缘光，并非只影响远处 NPC。

同一固定 NPC 场景的两轮模拟器比较中，边缘宽度设零会减弱右眼额外轮廓，恢复原值后重新出现。这支持临时抑制方案，不代表修复底层立体着色原因。头显验收及其他场景仍待验证。

关闭后，在仍由本选项持有该数值时恢复先前捕获的值。进入二维或原生 VR 不再活动时也会恢复；保持开启并返回适用的普通 VR 后会再次抑制。外部修改不会被覆盖。请读取选项下方状态，恢复失败不能视为成功。若提示重试，先关再开，系统会先重试恢复，再重新应用。

之后如选择测试，请固定远处 NPC 比较、检查近处画面取舍，再检查二维／返回及关闭后的恢复，详见 TEST THIS.txt。已有功能只需相关回归。

保留的视图控制

玩家已在此前 view-controls 版本确认头显二维亮度改善，本候选版保留该修正；独立 HUD／菜单透明度、RGB／伽马、双眼顺序及此前已接受的渲染修复保留。

切换立体二维：先将 LT 与 RT 按到底，再按住 L3 0.8 秒；重复前松开三者。关闭 UEVR 和 HUD／鼠标调整，对话中也可使用。返回普通 VR 后如 HUD 被压扁，在 VR → WuWa Controls → Reset HUD aspect 刷新并查看结果；不会发送 ESC 或修改保存的大小／位置。

水平 Horizontal Projection、垂直 Vertical Projection 默认仍为 Raw / default，不改写已保存选择。独立限时投影对比默认不运行，边缘光抑制会干扰对比时不允许启动。

过场右眼场景缺失／闪烁仍是已知问题；玩家反馈手动立体二维有帮助，但不自动切换过场。

已有功能：可选 Quest 漫游控制

打开 VR → WuWa Controls → VR 控制器漫游（可选）→ 漫游输入，每次启动默认关闭。使用 OpenXR，唤醒两侧控制器，将焦点切回游戏，再松开 VR 按键、握持键、扳机并让摇杆回中。恢复焦点、重连、切换模式或开关 UEVR 后需重复。第一人称仍是已有的独立选项；不更改相机和瞄准设置。

仅 VR 控制器在槽位 0 提供输入：左摇杆移动、右摇杆转动视角。VR + 跑步机／Xbox 槽位 0–3合并明确选择的已连接槽位。在故障排查 → 手柄检查查看后，确认设备对应槽位；编号本身不能识别 RealityRunner。合并完整保留设备左摇杆输入，包括静止状态；添加 VR 按键及右摇杆视角。实体右摇杆超过死区时，由它控制两轴视角。

Quest A/B/X/Y 与印字对应；扳机 = LT/RT，握持键 = LB/RB，摇杆点击 = L3/R3。左 Menu = Start；左握持键 + Menu = View（不发送 LB）。同时按下两侧摇杆开关 UEVR。UEVR 菜单始终使用 VR 左摇杆导航，即使处于合并模式；跑步机移动不会滚动菜单。不映射 Quest 系统键或十字键；这不是完整战斗布局。

手柄直通或槽位筛选冲突会阻止 VR 输入；不会修改驱动、HidHide、RealityRunner 或系统设置。关闭（常规输入）恢复原有 ControllersAllowed 行为：若该设置原已开启，旧版 VR 映射会恢复。关闭漫游不会关闭那项既有映射。

如选择测试，仅按 TEST THIS.txt 做相关漫游回归：RealityRunner 合并及菜单导航、按住输入时的恢复、快捷键与关闭／重启；明确记录通过／失败／受阻／未测试。已有功能仅需相关回归检查。如感到不适请停止；本模式不修复渲染问题。

Xbox 仍是默认游戏输入。微缩世界、裸手骨架和菜单舒适选项默认关闭。裸手只用于演示，不含抓取或手势玩法。

已有手柄视角切换

关闭 UEVR 设置及游戏菜单，并退出 HUD／鼠标调整。按住 L3（按下左摇杆），再将 LT 按到底切换空间窗口，或将 RT 按到底切换微缩视角。保持另一侧扳机松开；再次操作前松开所有按键。F7 仍切换空间窗口。手柄直通会绕过这些手柄快捷键。

微缩视角临时使用 10 倍世界比例，仅支持 Native Stereo，AFR 会禁用；空间窗口开关均可。关闭后恢复普通已保存比例，主动修改的比例也会保留。每次启动、重新加载设置或重新初始化运行时后默认关闭。头部移动也会放大，偏移时用 L3 + A 重新居中。菜单开关仍在 VR → WuWa Controls → Diorama mode (optional)。

保留 10 月 4 日 controller-toggles 修订的快捷键，请用新增漫游输入做回归检查。此前的组件验证不代表本候选版已通过实机验收。没有新增键盘快捷键。

保留已通过头显确认的大招镜头修复。新增可选功能仍待实机确认；NPC 立体光照的底层原因及武器／声骸子菜单反射仍未解决。统一检查表及验证边界见 TEST THIS.txt。
